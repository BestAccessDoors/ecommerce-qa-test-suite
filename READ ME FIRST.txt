============================================================
  BEST ACCESS DOORS - WEBSITE TESTS
  Quick start for non-technical users
============================================================

These tests act like a robot customer: they open the
websites, fill out forms, click around, and check that
everything still works. Everything runs in Google Chrome.

The EASIEST way is the Dashboard: a friendly page in your
web browser with buttons and colored results. Just
double-click one file. (The old ".bat" files still work
too - see "OLD WAY" near the bottom.)


------------------------------------------------------------
  STEP 1 - ONE-TIME SETUP  (only the very first time)
------------------------------------------------------------

  Double-click:   First Time Setup.bat

  It installs everything the tests need - including Node.js
  itself if you don't already have it. You don't have to
  download or install anything by hand.

  This takes 10-20 minutes the first time, mostly downloading.
  Leave it alone until it says "ALL SET!", then close the window.

  Notes:
    - It may create a "tools" folder here holding its own private
      copy of Node.js. That's normal. Nothing else on your
      computer is changed, and deleting the folder is safe (setup
      just downloads it again).
    - Setup normally needs no permission at all. Windows only asks
      if someone has turned on the optional machine-wide install
      (SETUP_MACHINE_NODE=1). If it does ask, Yes or No are both
      fine - it works either way.

  You also need Google Chrome installed (most computers
  already have it).  Get it at:  https://www.google.com/chrome


------------------------------------------------------------
  STEP 1b - THE CHECKOUT TEST PASSWORD  (optional)
------------------------------------------------------------

  One test pretends to be a real customer buying something:
  it puts an item in the cart, goes to checkout, and signs in.
  It stops before paying - it never places a real order.

  That is true for EVERYTHING you can start from these
  launchers or from the Test Dashboard. There is a separate
  command, meant for the technical team only, that does place
  a real order to check the payment step works end to end.
  It cannot be started by accident: it needs two switches set
  on the command line, and the dashboard deliberately removes
  them. Nothing you double-click here can order anything.

  Because it signs in, it needs the test account's email and
  password. Those are NOT in this folder, on purpose.

  To turn it on:

    1. Find the file:   credentials.example.json
    2. Make a copy of it in this same folder.
    3. Rename the copy to:   credentials.json
       Careful: Windows usually hides the ".json" part of file
       names. If the copy shows as "credentials.example - Copy"
       with no ".json", rename it to just:   credentials
       (otherwise it becomes credentials.json.json and is
       ignored - the tests print a warning if that happens).
    4. Open it in Notepad and replace the REPLACE_ME bits
       with the sign-in details you were given.
    5. Save. That's it - every way of running the tests
       picks it up automatically.

  Ask whoever set this up for the details. They are kept in
  the team password manager.

  IMPORTANT: never email credentials.json, never put it in a
  shared folder, and never send it in a chat message.

  If you skip this step, nothing breaks. Everything else still
  runs, and the checkout test simply shows as "skipped" - which
  is not a failure.

  RIGHT NOW (since October 12 2026) the checkout tests show as
  "skipped" on every store EVEN WITH the password in place: the
  stores switched on an anti-robot check (reCAPTCHA) at checkout
  that a test robot cannot get past. The skip says so in its
  name. The technical team re-enables them when that check is
  turned off. Nothing for you to do.


------------------------------------------------------------
  STEP 2 - OPEN THE DASHBOARD  (the easy way)
------------------------------------------------------------

  Double-click:   Test Dashboard.bat

  Google Chrome opens automatically. In the page:
    1. Tick the store(s) you want to test (or "Select all").
    2. Click  "Run selected".
    3. Watch the colored cards fill in as each store finishes.

  Green = all good.  Grey = a few tests failed.
  Orange/Red = more is broken.
  Click a red card to see the failing tests, open the
  screenshot, or play the video of what happened.

  Leave the small black window open while you work - it's
  the engine. Closing it stops the dashboard.


------------------------------------------------------------
  STEP 3 - READ THE RESULTS
------------------------------------------------------------

  In the Dashboard, each store gets a card:
    - PASS (green)   = working
    - FAIL (grey/orange/red) = something is broken - click to see
        (grey: most tests passed; red: most did not)
    - pending / skipped = turned off on purpose (not a problem)
        e.g. a store that doesn't have that form, or the
        checkout tests (see STEP 1b - currently skipped on every
        store on purpose). The reason is written right
        in the test's name, in square brackets.

  The "History" tab shows every past run.

  Results are also saved to:   results\test-results.log
  Failure screenshots are in:  cypress\screenshots\
  Failure videos are in:       cypress\videos\


------------------------------------------------------------
  OLD WAY - RUN FROM A BLACK WINDOW (still works)
------------------------------------------------------------

  To test EVERY store, double-click:   Run All Tests.bat
  To test just ONE store, double-click: Run One Store.bat
     ...then type the store number and press Enter.

  A black/white window with scrolling text is normal.
  When it finishes, scroll up to see PASS / FAIL.


------------------------------------------------------------
  IF SOMETHING GOES WRONG
------------------------------------------------------------

  - Take a screenshot of the window (red text and all).
  - Send it to whoever set this up for you.

  Most problems are fixed by double-clicking
  "First Time Setup.bat" once more.
